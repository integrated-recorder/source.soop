# First release vs current compatibility

Scope: compare public release commit `8366328d0968c16942045f1ccb0c65c98172cbbc` with the current working tree based on `41309cb826e6a673d597a99423526c2369d5cebc`, plus the changes in this report. The previously committed q=32/1080p profile is preserved.

| Area | First public release | Current tree before this change | Result / remaining boundary |
|---|---|---|---|
| B-frame timing | Progressive POC type 0 only; required fixed VUI timing and derived PTS from POC plus a reorder lead. It rejected missing/non-fixed timing as `h264_timing_unconfirmed`. | Grid composition supplies PTS; observed Grid decode timestamp supplies DTS. POC validates order, not elapsed time. No fixed-FPS timestamp synthesis. | Broader timing source: current can use Grid composition where the release required fixed VUI. We replayed identical 30-frame libx264 B-frame input through both implementations: both accepted all 30 and both PTS orderings matched FFprobe display order. |
| POC conflict | Bounded POC/PTS checks existed, tied to the release's HRD/VUI-derived timeline. | Explicit Grid-composition PTS is checked against parsed POC display order, DTS monotonicity, and reorder bound. | Current checks are more directly tied to observed Grid timestamps. A conflict remains fail-closed. |
| `frame_num` | Parses frame_num for POC calculations; no previous-reference frame_num continuity guard in this release implementation. | Tracks previous reference frame_num, MaxFrameNum, SPS gaps flag, IDR/MMCO5 state and emits bounded diagnostics on `h264_frame_num_gap`. | The V8 `119→1` transition is not a 7-bit modulo wrap: successor of 119 is 120; wrap is 127→0. Without the original SPS/reference context it remains correctly rejected when gaps are forbidden. |
| MMCO5 | The release parser does not parse dec_ref_pic_marking/MMCO5. | Parses MMCO5 and its reference/POC effects, but production timing subset explicitly rejects MMCO5 as `h264_grid_mmco5_unverified`. | Detection improved; production support is still intentionally absent because the complete Grid epoch/POC interaction is not independently validated. |
| POC type 1 / 2 | POC type 1 and 2 rejected; type 0 only. | Parses and computes POC 0/1/2; previously production rejected type 1 and briefly relaxed a Type-2 sequence rule in `41309cb`. | This task enables Type 1 only after offline StreamIO and independent decode validation, restores the normative Type-2 adjacent-non-reference rejection, then verifies all three types in short self-broadcast Grid runs. Type-1 live evidence is no-reorder; Type-2 live evidence is zero-reorder. See [support matrix](POC_TYPE_SUPPORT_MATRIX.md). |
| PCR gap | PCR was attached to each video PES DTS; there was no bounded interpolation or two-second gap failure. | Rejects non-increasing PCR time and gaps over 2 seconds; adds adaptation-only PCR packets at 100 ms media-clock steps for intermediate gaps. | TS PCR values become bounded without changing PES timestamps or elementary payload. This does not pace packet arrival in real time and does not prove media existed inside a source timestamp gap. |

Three exact repeated frame identities in the retained 60-second raw capture were deduplicated in-memory before parser comparison; no conflicting identity was found. |
| Cache/live transition | Initial implementation had a simpler Cache-to-live path. | Current recovery validates overlap/identity and fails closed when a continuous transition cannot be proven. | Not changed by this task; no startup retry behavior was altered. |

## Same-input differential evidence

1. **Synthetic B-frame sequence:** a local FFmpeg/libx264 30-frame, 30 fps stream with 18 B pictures and independently established FFprobe display order was passed to the release and current H.264 clocks. Both accepted 30/30, both had strictly increasing DTS, unique PTS, and PTS-sorted order equal to FFprobe display order. This demonstrates the newer composition-clock implementation did not regress this fixture; it does not establish arbitrary stream compatibility.
2. **Retained raw Grid capture:** the same 60-second authorized local Grid-wire capture was replayed in-memory through the release and current H.264 parsers after skipping three byte-identical repeated frame identities. Current accepted 3,591 VCL access units, had no parser errors, and treated remaining pre-IDR input as bounded preroll. The release failed 30 access units with `h264_timing_unconfirmed`, then reported `h264_parameter_set_missing` for 3,639 because its rejected SPS was not retained. This is a parser-level replay, not a full old-version MediaSink/TS replay. The capture is not the community V3/V5/V8 source bitstream.
3. **TS/PCR:** the current deterministic 231 ms recovery fixture passes independent TS/PES checks and full FFmpeg decode; see [TS_PCR_COMPATIBILITY_AUDIT.md](TS_PCR_COMPATIBILITY_AUDIT.md).

The reporter's modified V3/V5/V8 source and original failing media were not available, so exact reproduction of those private patches is not claimed.
